# 四渠道限流故障转移与候选耗尽

2026-10-14 需求对齐：限流故障转移适用于 WorkBuddy、TraeWork、CodeBuddy 国际和 WorkBuddy 国际，并覆盖项目已有的对外模型调用协议。一次账号限流优先自动换号，不直接把该账号的错误作为整个请求的结果；同渠道继续选择可用账号，再按既有模型优先级尝试允许的其他渠道。模型 ID、Key 渠道绑定、模型白名单、全局模型开关及账号调用开关始终有效，不为切换扩大请求权限。

用户明确选择：“如果账号都报错了，那肯定就返回报错”。所有符合条件的候选均失败或暂时不可用时，返回真实错误；不增加等待整个号池解冻的排队阶段，也不无限重试。该决定取代上一轮提出的“候选耗尽后等待最多 60 秒”的方案。

账号冷却和请求等待是两件事。冷却优先遵循上游明确的恢复时间；缺失时间时，按用户已确认的完整对齐卡采用默认 60 秒，允许在设置中调整。冷却只是让后续请求暂时避开受限候选，不要求当前请求原地等 60 秒。候选全部因限流不可用时，保留限流原因与可用的重试时间；其他错误不一律改写成 429。

各渠道按自己的上游响应识别限流，不把腾讯业务码直接套用于其他客户端。已有输出的流式请求不通过重新生成另一份回答来掩盖中途失败；管理员指定账号的测活仍报告那个账号自身的结果，不用另一个账号成功来替代。

限流与额度耗尽、凭证失效、管理员停用分别表达。限流不自动删除账号，也不为解除冷却自动发起模型测试；凭证维护和每日奖励不因模型调用冷却而被整体停用。

本记录确认需求边界及规格默认值。2026-10-14 用户回复“可以，下一步”，已批准规格编写与发布；任务拆分、代码实现、提交推送与部署尚未获本轮移交许可。
