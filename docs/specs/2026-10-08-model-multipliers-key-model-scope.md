## 问题说明（Problem Statement）

1. 模型页只有名称、模型 ID 和开关，看不出某个渠道的模型免费还是按何种倍率计费；相同名称、不同线路也容易混淆。
2. API Key 当前仅支持绑定单一渠道或全池，没有模型白名单，管理员难以把一个 Key 的调用范围限制到若干模型。
3. Key 的选项必须服从模型页全局开关：模型页关闭的模型在 Key 多选区灰显、不可点击，而不是另建一套脱离全局设置的可选目录。
4. 增加以上功能时，需要保持旧 Key、外部 OpenAI 兼容格式、渠道优先级、账号维护及已有全局开关的行为。

## 解决方案（Solution）

### 模型页

在四个渠道各自的模型条目旁显示「免费」「×倍率」或「未公布」。数据来自对应渠道的官方配置，随现有目录同步更新；缺失倍率不是免费，同名模型也不共用价格。

倍率仅用于管理界面提示，不参与自动选路或修改计费。顶部跨渠道聚合模型区维持原展示，不为跨渠道同名模型强行给出一个价格；公共 `/v1/models` 的响应结构保持原样。

### API Key 页

保留渠道绑定，增加「不限模型 / 指定模型」。指定模式支持多选，创建或修改名单时至少选择一个当前可选模型；历史 Key 默认不限模型，新模型不自动加入已有白名单。已有 Key 可编辑渠道与模型范围，密钥字符串保持不变。

| 模型页全局状态 | Key 自己是否选中 | Key 多选区表现 |
|---|---|---|
| 当前渠道范围内开启 | 未选中 | 正常显示，可勾选 |
| 当前渠道范围内开启 | 已选中 | 正常显示，可取消 |
| 当前渠道范围内关闭 | 未选中 | 灰显，选项不可点击，提示「模型页已关闭」 |
| 创建 Key 后被全局关闭 | 历史已选中 | 已选标签保留并标记停用；选项灰显，实际调用停用 |

“未选中的都变灰”指模型页没有开启的模型，不是把 Key 多选框里尚未选择的正常模型也锁住。

对外清单和实际调用都取 Key 模型范围、渠道绑定、全局开关的交集。只隐藏列表不足以实现限制，直接填写模型 ID 的请求同样检查权限。

## 用户故事（User Stories）

1. 作为管理员，我希望直接看到每个渠道模型的倍率，以便区分免费和付费线路。
2. 作为管理员，我希望只有上游明确零倍率才显示免费，以免把未知价格当作免费。
3. 作为管理员，我希望没有明确官方倍率的条目显示未公布，以免看到推测价格。
4. 作为管理员，我希望相同模型在各渠道分别显示倍率，以免跨渠道价格混用。
5. 作为管理员，我希望免费与付费线路保留各自准确的模型 ID，以便选择正确线路。
6. 作为管理员，我希望刷新目录同时更新倍率，而且不触发推理，以免为查看价格消耗积分。
7. 作为管理员，我希望刷新失败保留并标记上次成功数据，以免旧数据被伪装成最新结果。
8. 作为管理员，我希望新建 Key 时可以选择不限模型，以继续使用已有全池或单渠道用法。
9. 作为管理员，我希望一个 Key 可以选择多个模型，以便给不同调用方分配不同范围。
10. 作为管理员，我希望指定模式至少选择一个模型，以免空名单被误解为允许全部。
11. 作为管理员，我希望模型页关闭的模型在 Key 选择区灰显且不可点击，以免误授权。
12. 作为管理员，我希望模型页已开启但尚未加入 Key 的模型保持可选，以便正常多选。
13. 作为管理员，我希望选定渠道后，Key 候选项遵守该渠道的目录和开关，以免别的渠道覆盖限制。
14. 作为管理员，我希望全池模式将同一 ID 去重，并允许从仍开启的渠道调用，以继续使用既有优先级。
15. 作为管理员，我希望可以搜索名称或模型 ID，以便从较长的多选列表里找到目标。
16. 作为管理员，我希望可以编辑已有 Key 的渠道和模型范围，而无需让调用方更换密钥。
17. 作为管理员，我希望编辑失败保留原权限和表单内容，以免部分保存造成误授权。
18. 作为管理员，我希望旧 Key 升级后保持不限模型，以免现有调用突然中断。
19. 作为管理员，我希望新发现的模型不自动加入指定模式 Key，以便权限始终由勾选决定。
20. 作为管理员，我希望关闭全局模型后，既有 Key 也立即停止对它的新调用，以保持全局开关的权威性。
21. 作为管理员，我希望历史白名单中的停用模型仍可辨认和移除，以便整理配置而不是悄悄丢失选择。
22. 作为管理员，我希望切换绑定渠道后能明确看到失效选择，以免静默把请求转去别处。
23. 作为调用方，我希望 `/v1/models` 只列出自己的 Key 获准且渠道已开启的模型，以便直接选用。
24. 作为调用方，我希望模型清单仍是原有 OpenAI 兼容结构，以免客户端因新增价格字段发生兼容问题。
25. 作为管理员，我希望手动提交未获准模型的请求也被拦截，以免只靠界面隐藏限制。
26. 作为管理员，我希望聊天、Responses、图像及其现有别名入口执行相同权限规则，以免换个协议就突破模型范围。
27. 作为管理员，我希望系统默认选择和内部替换也遵守白名单，以免内部流程调用未选模型。
28. 作为管理员，我希望名单存储异常时保持收紧状态，以免损坏配置被当作不限模型。
29. 作为管理员，我希望权限修改对保存后的新请求生效，并保留现有调用统计，以便准确管理。
30. 作为管理员，我希望测试使用临时账号库和模拟上游，以免为了开发这两个功能消耗正式账号额度。

## 实施决策（Implementation Decisions）

### 1. 范围及模块职责

- 扩展平台目录适配与持久化、管理端模型条目、Key 管理及公共请求鉴权；复用现有目录刷新、路由、全局开关和优先级。
- 四渠道均显示统一的倍率状态；上游缺少可核验字段时使用「未公布」，不为了齐全编造倍率。
- 倍率属于“渠道＋模型 ID”，Key 白名单属于“Key＋模型 ID”。Key 的渠道范围仍是现有的单渠道或全池，不新增逐模型绑定渠道的另一套优先级。
- 图像及其他已登记类型也适用模型权限，调用仍使用现有协议；不借此增加新的生成协议。

### 2. 官方倍率数据与展示

- 目录适配在读取当前官方目录时同时提取倍率元数据，模型列表与倍率采用同一来源快照，避免为同一账号重复查询。
- 腾讯系渠道以当前官方模型元数据的 `credits` 等已验证字段为依据；Trae 仅映射经过验证的官方倍率字段，缺省或语义不明时显示「未公布」。
- 支持当前已观察到的 `x0.03`、`x0.34 credits` 格式；准确的数值零显示「免费」，正倍率显示如「×0.03」。空字符串、缺字段、无效数值和解析异常均不当作零。
- 保留上游精度，避免把很小的正倍率四舍五入成免费；不将绝对单价、促销说明或上下文大小误读为倍率。
- 为渠道模型保留官方原值、正规化结果、来源及最后成功获取时间；不保存账号凭证到价格元数据，不因价格状态修改实际积分账本。
- 单次成功响应明确缺少倍率时，更新为「未公布」；请求失败时保留上次数据并显示旧数据/同步失败状态，二者不混为一谈。
- 同渠道账号返回相互矛盾的倍率时，不按最便宜账号或最后一个账号覆盖成统一价格；主标记显示「未公布」，说明中提示账号返回不同并保留可核验来源。
- 刷新失败、无可用账号、部分账号失败继续遵守现有目录保留策略。无账号的渠道不自动借用其他渠道凭证、复制账号或改动归属。
- 价格与“已测活”“永久免费”“无限使用”是不同概念；任何目录同步或查看价格的操作都不触发聊天、生图或音频生成。

### 3. Key 数据及兼容契约

- Key 增加显式 `model_scope`：`all` 表示不限，`selected` 表示指定；`allowed_models` 为确切模型 ID 数组。数据存储采取增量迁移，历史行迁入 `all`，现有 Key 字符串、绑定、启停和计数保持原值。
- `selected` 与空名单不是 `all`。创建或改变指定名单时要求非空；历史配置损坏、未知模式或指定名单解析失败时不放宽权限，对外清单为空、调用失败，并在管理端报清配置问题。
- 旧的创建请求省略两个新字段时沿用不限模型；更新请求省略新字段时保持原配置。显式提供字段需严格校验类型、模式和值，不把错误输入悄悄转换为不限。
- 模型 ID 去掉首尾空白并去重，但不改大小写、不合并不同线路、不把展示名当成 ID。新增选择只接受当前注册表中符合所选渠道范围且已开启的模型。
- `all` 模式不携带生效白名单；切换到 `all` 时明确清空白名单。切回 `selected` 时重新选择至少一项，避免隐藏的旧配置重新生效。
- 编辑渠道和模型范围原子保存，任一校验失败则整次更新不生效；不通过删除重建或轮换 Key 来实现编辑。
- 重复创建已存在的自定义 Key 应报冲突并保留原 Key，不以“创建成功”掩盖新权限没有落地。

### 4. Key 选择区与全局开关联动

- 使用带搜索的多选列表，显示名称及模型 ID，已选数量和选择结果明确可见；模式切换与渠道绑定位于创建/编辑表单中。
- 绑定单渠道：候选来自该渠道目录；其中模型页关闭的条目保留显示，但灰显、禁用鼠标与键盘选择，并有“模型页已关闭”的原因提示。
- 全池：按模型 ID 合并各渠道目录；只要任一支持渠道仍开启，该 ID 可选；全部支持渠道关闭才灰显。实际调用仍只进入开启的渠道并沿用原优先级。
- 同一模型在其他渠道开启，不会使已绑定渠道里关闭的项变成可选；价格信息也不产生额外权限。
- 渠道切换后重新计算候选状态；已有选择若不再属于该渠道或已关闭，保留为标明原因的失效标签，不静默映射成其他模型。
- 历史已选项在全局关闭后仍可显示为失效标签；禁用选项本身保持不可点击，另用已选标签的移除操作清理。恢复全局开启后，原有白名单 ID 可以恢复生效，这不是自动加入新 ID。
- 创建或修改模型名单、渠道时，提交名单需满足当时的可选范围；失效项须移除或恢复全局开启后再提交。仅启停 Key、未变动名单/渠道的请求不自动删掉历史选项。
- 打开编辑器和改变渠道时更新可选状态，保存时后端再次校验。表单打开后若模型被关闭，保存报明具体失效项并保留输入，而不是依据旧页面放行。
- 选项数据加载失败时保留已有值并明确报错，指定模式停止提交，避免空候选列表被保存成不限模型。

### 5. 管理 API

| 接口 | 本次行为 |
|---|---|
| `GET /api/keys` | 保留旧字段，增加模型范围和名单，管理页能区分不限与指定 |
| `POST /api/keys` | 接受新字段，按当前目录、渠道和开关校验；非法名单返回400，重复自定义 Key 返回409 |
| `PATCH /api/keys/{id}` | 支持编辑渠道、范围和名单，保留既有启停功能；省略字段原样保留；不存在返回404 |
| 现有管理模型目录读取/刷新接口 | 增加可选倍率元数据，保留现有字段；只读状态接口不访问上游生成接口 |
| `GET /v1/models` | 只过滤 Key 可见模型，保持 `object`、`data` 及条目 `id/object/created/owned_by` 的原有格式，无价格字段 |

- 不新增或改名公共模型接口；用户所说的 `v1/model` 对应本项目既有 `/v1/models`。
- 管理端使用完整目录与全局开关渲染灰色选项，而不是拿过滤后的公共列表代替完整目录；因此“全局关闭的模型仍在管理多选区可见”与“外部列表隐藏它”并不矛盾。
- `/v1/models` 对合法但有效模型交集为空的 Key 返回正常空列表，不回退成全部模型。

### 6. 实际请求权限

- 模型范围校验在实时探测、渠道路由、账号选择和上游生成前执行；指定模式对白名单外、已关闭或当前渠道不支持的模型返回清晰403，不发起探测验证它是否也许能用。
- 当前存在的聊天、Responses、图像请求及对应别名入口共用同一规则；所有既有 API Key 传入方式保持兼容。管理端主动测活仍由管理员权限控制，不套用某个外部 Key 的白名单。
- 显式请求的模型 ID 与经既有默认/内部替换后真正调用的模型均要检查；不存在“原请求在白名单，换成白名单外模型却继续调用”的路径。
- 不给用户新增缺省模型设置。保留现有端点的必填参数和默认选择逻辑，解析出的模型未获准时直接报错，不偷偷换成另一个允许模型。
- 全局关闭、Key 编辑和启停对保存后的新请求生效；已发出的上游请求不在此功能中强制中断。外部客户端自行缓存的模型列表可能暂时旧，但新请求的后端校验始终读取生效权限。
- 指定模式下已移出目录的历史模型不因调用而触发重新探测复活。不限模型 Key 的既有外部未知模型处理保持原边界；本次不改写全站模型发现策略。

## 测试决策（Testing Decisions）

### 测试入口

优先使用两个现有高层入口，不为测试拆出一套仅测试使用的权限实现：

1. **应用 HTTP 边界**：管理 API 创建/编辑/读取 Key，读取/刷新模型目录，再带 Key 访问公共模型列表及现有生成接口。使用临时数据库和可控上游响应，检查可观察结果及是否真的发生上游调用。
2. **真实浏览器管理页面**：沿用现有浏览器＋临时数据库测试方式，操作模型页开关与 Key 多选/编辑表单，核验灰显、键盘禁用、持久化和错误提示。

数据库迁移用旧版临时库启动应用，再通过管理/公共 API验证旧 Key 行为；价格解析通过模拟官方目录响应后的管理接口和页面验证。沿用已有开关联动、目录同步、登录表单浏览器测试风格，不把测试绑在内部函数名或 SQL 布局上。

### 必须覆盖的场景

| 编号 | 验证点 | 通过标准 |
|---|---|---|
| T01 | 旧库与旧创建请求 | 旧 Key 继续不限模型，字符串、绑定、启停、统计保持原值 |
| T02 | 新建及多选 | 指定模式选1个或多个当前开启模型成功；空名单、非法类型、未知ID失败 |
| T03 | 灰显语义 | 全局关闭项鼠标和键盘均不可选；全局开启但 Key 未选项仍可勾选 |
| T04 | 绑定渠道 | 其他渠道开启不越过绑定；全池按ID去重且只走开启渠道 |
| T05 | 编辑及重载 | 用同一 Key 编辑后刷新页面仍正确；渠道与名单更新失败时全部保持原值 |
| T06 | 动态关闭 | 表单打开后模型关闭，保存失败且说明具体条目；已保存 Key 对该模型的新请求停用 |
| T07 | 历史失效项 | 原名单保留、灰标签有原因且能移除；再次开启后只恢复原ID；全失效时外部列表为空 |
| T08 | 模式切换 | all与selected转换明确；指定空名单不变成all；新模型不自动加入指定Key |
| T09 | 公共模型列表 | 按模型、渠道、开关交集过滤；原字段结构不变，不增加倍率或其他管理字段 |
| T10 | 所有请求入口 | 聊天、Responses、图像及现有别名、流式/非流式、各鉴权方式同样校验 |
| T11 | 越界零调用 | 白名单外请求返回403，上游生成与未知模型探测调用次数均为0；允许模型仍走正常链路 |
| T12 | 默认和替换 | 真实模型落在白名单外时停止；现有必填参数错误保留；没有新增用户配置 |
| T13 | 异常权限及重复Key | 损坏/未知模式不扩大权限；重复创建报409而非假成功，不修改原Key |
| T14 | 倍率正规化 | x0.00显示免费，x0.03显示×0.03，x0.34 credits显示×0.34；缺省及无效值显示未公布；极小正值不显示免费 |
| T15 | 渠道隔离 | 同ID跨渠道可以显示不同倍率；免费/付费不同ID保持独立；相互矛盾账号样本有说明 |
| T16 | 刷新和缓存 | 同一官方配置同时同步目录及价格；刷新失败显示旧数据；成功缺字段更新未公布；查看和刷新均不触发生成 |
